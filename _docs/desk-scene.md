# Desk scene: technical design

Status: M0 to M4, the M6 props and the promotion to `/` are done. Real-device checks have not run. Owner: Alex S. Last updated: 2026-11-09.

## Summary

The blog gets a new home page. It is a dim room with a desk. A beige-white desktop PC lies flat on the desk with a CRT monitor on top. The visitor presses the power button, the machine boots, and a Linux terminal appears on the screen. The terminal is the way to find and read posts.

The scene is an enhancement. Jekyll still builds every post as a plain HTML page at its current URL, and a plain post list stays one click away at all times.

This document fixes the scope, the decisions, the architecture, and the build order. It does not contain implementation code beyond short examples.

## Era

The machine is a desktop PC from around the year 2000, the end of the Windows 95/98 period. Every visible detail follows that year. The same year also had Linux: Slackware, Red Hat 6.x, and kernel 2.2 or early 2.4, so a Linux terminal on this machine is accurate and not an anachronism.

| Detail | Value for the scene |
| --- | --- |
| CPU and memory | Pentium II or III class, 64 MB RAM |
| BIOS | Award-style blue text screen. The memory test counts up to `65536K OK` |
| Case | Beige-white plastic, slightly yellowed. A 3.5" floppy drive, a CD-ROM drive (24x), a power button, a reset button, a power LED, and an HDD LED |
| Not on the case | No turbo button (a 386/486 feature) and no USB ports on the front |
| Monitor | 15" or 17" CRT, 4:3, thick bezel, a brightness dial and a power switch |
| Boot loader | LILO prompt, then a kernel 2.2.x log |
| Props | A floppy disk, a CD-R in a paper sleeve, a beige keyboard and ball mouse, a CRT-era speaker pair |
| Not in the scene | Flat screens, USB sticks, phones, anything after 2001 |

## Goals and non-goals

Goals:

1. From the READY state, a visitor finds and reads any post from the terminal in under 10 seconds, with the keyboard only. A visitor who wants content before the boot uses the "Skip to posts" link.
2. The power-on and boot sequence feels physical: button travel, degauss thump, fan spin-up, a phosphor warm-up, and a boot log.
3. Render time stays within 16.6 ms per frame on desktop and on an iPhone 11, and within 22 ms on a mid-range Android phone from 2021.
4. Old post URLs, RSS, and search-engine indexing keep working unchanged.
5. The site works without WebGL and without JavaScript.

Non-goals for the first release:

- Free-fly camera, multiple rooms, or a second computer.
- A real Linux in the browser (WebAssembly VM). The shell is a JavaScript simulation.
- A graphical session started with `startx`, shown as an IceWM or fvwm95 desktop with a Windows 95 look. It ships after the terminal is solid (milestone M6).
- Gyroscope parallax, VR, or multiplayer cursors.
- Rewriting the existing post layout beyond adding a "back to the desk" link.

## Decisions

| Topic | Decision | Reason |
| --- | --- | --- |
| Rendering | Three.js with WebGL2 | The CRT effect needs a shader. CSS 3D cannot do curvature or scanlines. |
| Models | Built from code (rounded boxes, canvas-drawn decals) | No asset pipeline, near-zero download size, easy to tweak. A glTF model can replace `models/pc.js` later because the interface is one function. |
| Screen | 2D canvas used as a texture, drawn by our own terminal code | Full control of the look, and one draw call. Cost is no native text selection. The accessibility mirror (below) covers screen readers. |
| Camera | Fixed position, drag range of about 18 degrees yaw and 10 degrees pitch | A diorama feel and no way to get lost. |
| Sound | On by default, synthesized with Web Audio, mute toggle persisted | Browsers block audio before a user gesture, so sound starts at the first click or key press. Synthesis means no audio files. |
| Start state | Machine is off, standby LED glows amber | The boot is the best moment of the experience. The always-visible "Skip to posts" link covers visitors who want content now. Revisit after the prototype. |
| Build | esbuild bundles `desk-src/` into a small loader plus split chunks under `assets/js/desk/`. A GitHub Actions workflow builds the bundle and the Jekyll site on each push and deploys to Pages. The bundle is not committed | The Pages branch build cannot run Node and pins Jekyll 3.10. The workflow runs the same Jekyll 4 and Node versions as a local build, and tests block a bad deploy. Splitting keeps the scene out of the first load. |
| Content source | `posts.json` generated by Jekyll, post bodies fetched on demand from the real post pages | One source of truth. No second copy of the posts to keep in sync. |
| Tests | Vitest for pure logic, Playwright for a smoke path | The shell, parser, and virtual file system are pure functions. 3D output is not worth pixel diffs. |

## Experience specification

### Machine states

The power controller is a state machine. Every other module reads its state and never sets it directly.

```
OFF -> POWERING -> POST -> BOOTING -> READY
POWERING, POST, BOOTING, or READY -> HALTING -> OFF
```

| State | Screen | Sound | LED |
| --- | --- | --- | --- |
| OFF | Black glass with a faint reflection of the lamp | Silent | Power LED amber |
| POWERING | White dot expands to a line, then to full height (400 ms) | Relay click, 60 Hz thump, fan noise ramps up over 1.2 s | Power LED green |
| POST | BIOS text, memory counter climbs to `65536K OK` | One 1 kHz beep (120 ms) | HDD LED flickers |
| BOOTING | LILO prompt, then about 40 lines of a kernel 2.2.x log, 15 to 60 ms apart | Seek-like noise bursts tied to log lines | HDD LED follows the bursts |
| READY | Login banner, then the shell prompt | Fan loop, key clicks | HDD LED idle, blinks on file reads |
| HALTING | "System halted", then the picture collapses to a dot (300 ms) | Fan winds down, thump | HDD LED off |

Timings:

- Cold boot takes about 5 seconds. Skip input during POWERING, POST, or BOOTING jumps to READY.
- After the first visit, `localStorage` key `desk.booted` is set and boot takes about 1.5 seconds.
- With `prefers-reduced-motion: reduce`, the machine goes from OFF to READY with no animation. Sound still plays unless muted.
- Pressing the power button in any state other than OFF and HALTING starts HALTING. In HALTING the button does nothing. HALTING always ends in OFF.
- `reboot` runs HALTING, then OFF, then POWERING with no pause.
- Skip input is any key press or click, with two exceptions. A press of the power button is not skip input, and follows the power-button rule above. The input that powered the machine on is not skip input either, including the `click` and `keyup` that follow its `pointerdown` or `keydown`.
- With `#cat=<slug>` in the URL, the machine powers on by itself, takes the fast boot path, and runs `cat` for that post at READY. Audio stays silent until the visitor's first click or key press.

### Interactions

- **Power button.** A 3D button on the case front. It depresses 2 mm on press and the click plays on release. A visually hidden `<button>` mirrors it so keyboard and screen-reader users can press it.
- **Orbit.** Drag on the background or the desk. Dragging has inertia and springs back slowly to center after 6 seconds of no input.
- **Focus mode.** A click on the screen while READY moves the camera in front of the monitor over 600 ms. A click outside the screen, or the second `Esc` (see Keyboard capture), returns it. In focus mode the orbit range shrinks to 4 degrees. When the narrow layout is active (see Terminal behavior), the camera enters focus mode by itself at READY, because the default view is unreadable at that size.
- **Keyboard capture.** Typing works whenever the machine is READY and focus mode is active, or the hidden input has focus. A hidden `<input>` receives the keys, which also makes mobile keyboards, IME, and paste work. `Tab` completes commands while the input has focus, so `Esc` is the way out. The first `Esc` blurs the input and moves focus to the mute button, the next element in the tab order. Focus does not go to the power button, because a habitual Enter there would shut the machine down. A second `Esc` leaves focus mode.
- **Props.** The lamp toggles room light on click. The floppy disk links to GitHub and plays an insert animation first. The sticky note shows the "now" page. The mug steams. A wall clock shows the visitor's local time. All props are optional for M1 to M5 and land in M6.
- **Mute.** A speaker icon in the top-right corner. State is stored in `localStorage` key `desk.muted`.

### Terminal behavior

The prompt is `alex@desk:~$`. The terminal has two layouts, 80 columns by 30 rows (wide) and 40 columns by 15 rows (narrow). See Screen canvas for the cell sizes. The terminal picks the wide layout when the screen is at least 600 CSS px wide on the display in focus mode, and the narrow layout below that. Focus mode is the reading view. In the default view, text is too small to read in either layout. It keeps 2000 lines of scrollback. The mouse wheel scrolls the scrollback while the screen has focus.

Commands in the first release:

| Command | Behavior |
| --- | --- |

- Tab completion for command names and paths, with a candidate list on a double Tab.
- Up and down arrows walk through history. History persists in `sessionStorage`.
- One level of pipe into `grep`, `head`, `tail`, or `wc -l`. Nothing else is piped in the first release.
- `Ctrl+C` cancels a running fetch and prints `^C`. `Ctrl+L` clears.

## Architecture

### Module layout

Source lives in `desk-src/` and builds to `assets/js/desk/main.js` plus split chunks. Each file lists its entry function first and its helpers below it.

```
desk-src/
	main.js               entry: feature detection, dynamic import of the scene
	power.js              the state machine and its timings
	scene/
		scene.js            renderer, render-on-demand loop, resize
		camera.js           limited orbit, focus tween, inertia
		picking.js          raycasting for button, screen, props
		lighting.js         lights, procedural environment map
		models/
			pc.js             the case, drives, button, LEDs
			crt.js            the monitor and the screen mesh
			desk.js           desk, mat, contact shadows
			props.js          lamp, mug, floppy, note, clock
	screen/
		screen-canvas.js    draws terminal cells to the 2D canvas
		crt-shader.js       GLSL for curvature, scanlines, mask, power curve
		font.js             loads the font and measures the cell
	terminal/
		terminal.js         line buffer, cursor, scrollback, input line
		shell.js            parser, dispatch, history, completion
		fs.js               virtual file system
		pager.js            the `less` implementation
		html-to-text.js     post HTML to wrapped terminal text
		commands/           one file per command
	audio/
		audio.js            context, master gain, mute, unlock on first gesture
		synth.js            beep, fan, thump, relay click, HDD bursts, key click
	a11y/
		live-region.js      mirrors terminal output into an aria-live region
		proxy-controls.js   hidden power button and input
	fallback.js           shows the plain post list
```

Tests sit beside the modules as `*.test.js`. In any file that contains tests, the tests come last.

### Data flow

1. `main.js` checks WebGL2 and `navigator.connection.saveData`. Only Chromium implements `saveData`, and no browser implements `prefers-reduced-data` yet, so the code does not use that media query. If either check fails, it calls `fallback.js` and stops.
2. It dynamically imports the scene, which esbuild emits as a separate chunk (see Build and deploy), so the plain page paints first.
3. The scene builds the models and renders one frame with the machine OFF. Only then does `main.js` add the class `scene-on` to `<html>`, which hides the plain list. If the import fails or the scene throws during setup, `main.js` calls `fallback.js` and never adds the class.
4. `power.js` owns the state. The scene, screen, terminal, and audio subscribe to its changes.
5. The terminal draws into `screen-canvas.js`. When the canvas changes, it sets a dirty flag. The scene uploads the dirty rows on the next frame and clears the flag (see Screen canvas).
6. Commands that need posts read `posts.json`, fetched once and cached in memory.

### Render loop

The loop renders on demand. It runs while any of these hold: the user is dragging, the camera is tweening, the machine is POWERING, POST, BOOTING, or HALTING, or an animation such as steam is active. In READY it renders at 30 fps for 10 s after the last input. After that it renders only when the terminal canvas is dirty (the 2 Hz cursor blink) and freezes the flicker. In all other cases it stops, so an idle OFF scene uses no CPU or GPU.

Pixel ratio is capped at 2 on desktop and 1.5 on mobile. The loop measures frame time over 60 frames. If the average exceeds 15 ms on desktop or 20 ms on mobile, about 90 percent of each budget, it drops the pixel ratio by 0.25 and disables bloom, down to a floor of 1. The threshold sits below the budget so the drop happens before frames miss it.

The renderer listens for `webglcontextlost` and `webglcontextrestored`, which mobile browsers trigger under memory pressure. On loss it calls `preventDefault()` and stops the loop. On restore it rebuilds the textures and resumes. If the context is not restored within 3 s, it calls `fallback.js`.

## Rendering

### Scene and lighting

- Perspective camera, vertical field of view 35 degrees. Starting position `(0, 38, 62)` cm, looking at `(0, 14, 0)`. These numbers are starting values to tune by eye.
- One warm directional light, one lamp point light (off until the lamp is on), and a procedural environment map from three.js `RoomEnvironment` for plastic reflections.
- No real-time shadows. A radial-gradient texture on a plane under each object fakes contact shadows. This costs nothing and looks right at this camera distance.
- The screen adds a faint blue-white glow to nearby surfaces. A soft additive sprite in front of the glass does this, scaled by the screen's average brightness, sampled once every 250 ms.

### Models

Dimensions are in centimeters, one scene unit per centimeter.

- Case. 42 wide, 14 tall, 43 deep, lying flat. `RoundedBoxGeometry` with a 0.6 radius. Material is `MeshStandardMaterial`, color `#d8d2c0`, roughness 0.55, with a generated grime map (a canvas with low-contrast noise and edge darkening) in the roughness and color channels.
- Front panel. A 3.5" floppy slot, a CD-ROM tray with a line of print, a reset button, a power button (1.6 cm, travels 2 mm), a power LED, and an HDD LED. There is no turbo button, because that part is from the 386/486 period. LED glow is an emissive material plus a small sprite.
- Monitor. 36 wide, 36 tall, 38 deep, with a tapered back made from a scaled box and a rounded front bezel. The glass is a slightly curved plane that carries the CRT shader.
- Decals. Case badge (a "Pentium III inside"-style sticker with an invented name), the CD-ROM speed label, and the monitor brand strip are drawn on small canvases and applied as textures. They use invented names. No real trademarks.
- Desk. A wood-grain plane drawn on a canvas at runtime, plus a green cutting mat.

All models come from `build*()` functions that return a `Group`. The scene calls them by name and does not read their internals, which lets a glTF version replace any of them.

### CRT shader

The screen mesh uses a `ShaderMaterial`. The fragment shader samples the terminal canvas texture and applies these steps in order:

1. Radial barrel distortion with `uCurvature` (default 0.05). Pixels outside the distorted rectangle are black.
2. A small horizontal blur to mimic the beam, taken from three texture samples.
3. Scanlines with `uScanline` (default 0.25). The scene passes `uScreenHeightPx`, the height of the screen mesh on the display in device pixels, and updates it on resize and on camera moves. The shader draws `min(480, floor(uScreenHeightPx / 3))` lines. 480 is one line per canvas row pair, and the 3-pixel minimum period avoids moiré when the 1280 by 960 canvas is downscaled. `uScanline` fades to 0 below 60 lines, two per text row in the wide layout, because coarser lines cut through glyphs.
4. An RGB aperture mask with `uMask` (default 0.15). One mask triad covers at least 3 device pixels, and the mask fades out below 60 triads across the screen height, as the scanlines do.
5. Vignette with `uVignette` (default 0.35).
6. Flicker with `uFlicker` (default 0.02) driven by `uTime`.
7. The power curve. `uPower` runs 0 to 1. Below 0.15 the output is a white dot. From 0.15 to 0.5 the dot stretches into a horizontal line. From 0.5 to 1 the line fills the height. Reverse for shutdown.

The canvas is 1280 by 960 pixels. The cell size is 16 by 32 pixels. That gives 80 columns by 30 rows.

In the narrow layout, the cell size is 32 by 64 pixels and the font renders at 2x. That gives 40 columns by 15 rows. If focus mode makes the screen about 360 px wide on a 390 px viewport, a column is about 9 px wide. The canvas size does not change. The terminal, `less`, and `html-to-text.js` read the column count from the active layout, and a resize that changes the layout reflows the buffer. The font is VT323 (SIL OFL), subset to ASCII and box-drawing characters, as a self-hosted `woff2` under 20 KB.

### Screen canvas

`screen-canvas.js` draws cells in two passes: backgrounds first, then glyphs. It redraws only dirty rows. The cursor blinks at 2 Hz and marks only its own row dirty. Text color is phosphor green `#33ff66` on `#021208`, with a user-visible `theme` command that offers amber and white-on-blue.

The scene uploads only the dirty rows to the GPU, as bands with `texSubImage2D`. It does not set `needsUpdate` on a `CanvasTexture`, because three.js then re-uploads the whole canvas, about 4.9 MB, which is about 150 MB/s at 30 fps. The texture has mipmaps so text stays smooth when the screen is small on the display. After each upload the scene calls `generateMipmap`, which runs on the GPU and costs far less than a full upload. Measure the upload cost on a real phone in M2.

## Audio

All sounds are synthesized with Web Audio. The release has no audio files.

| Sound | Recipe |
| --- | --- |
| Relay click | 8 ms noise burst through a 1.5 kHz band-pass, plus a 90 Hz sine decay |
| Degauss thump | 60 Hz sine, 250 ms exponential decay, plus a short low-passed noise tail |
| Fan | Brown noise through a low-pass at 400 Hz, with a slow 0.4 Hz gain wobble. Gain ramps over 1.2 s at start and 2 s at stop |
| POST beep | 1 kHz square wave, 120 ms, low gain |
| HDD seek | 15 to 40 ms noise bursts through a 2 kHz band-pass, triggered by boot lines and file reads |
| Key click | 6 ms noise through a 3 kHz band-pass plus a 180 Hz thump, with random detune per key |

Rules:

- The `AudioContext` is created and resumed inside the first `click`, `pointerup`, or `keydown` handler. `pointerdown` and `touchstart` do not unlock audio on iOS Safari, so the code does not use them. Before that, audio calls are no-ops.
- Master gain is 0.5. Fan gain is 0.06. These values are a starting point, tuned with headphones and laptop speakers.
- Mute sets master gain to 0 and suspends the context after 300 ms so it uses no CPU.
- Audio stops when the tab is hidden (`visibilitychange`).

## Accessibility and fallbacks

- **Plain list.** A "Skip to posts" link is the first focusable element. It reveals the same list the fallback uses. The `exit` command does the same. The list is real HTML in `desk/index.html`. CSS hides it only under the `scene-on` class on `<html>`, which `main.js` sets after the scene renders its first frame. With no JavaScript or no WebGL, the list stays visible. The skip link and `exit` add the class `list-open`, which shows the list again.
- **Screen reader mirror.** `live-region.js` copies each new terminal line into a visually hidden `aria-live="polite"` region. Prompt text is not mirrored. The boot log (POST, LILO, kernel) is not mirrored either. The region announces "System ready" once at READY. A `cat` of a long post is mirrored as one block with the title as its label.
- **Keyboard path.** The tab order is the skip link, the hidden power button, the hidden input, then the mute button. Enter on the power button powers the machine. Typing then works with no mouse. `Esc` in the input moves focus to the mute button, so the input never traps focus (WCAG 2.1.2).
- **Visible focus.** When the hidden power button has focus, the 3D button shows the same highlight as on hover. When the hidden input has focus, the cursor blinks. Without focus, the cursor is a hollow block. This meets WCAG 2.4.7 for controls that are visually hidden.
- **Reduced motion.** No boot animation, no camera tween, no flicker, no steam. Orbit is disabled.
- **No WebGL or no JavaScript.** The page ships the post list in HTML. The scene replaces nothing until it initializes successfully.
- **Contrast.** The source colors of each theme meet 7:1 contrast. Scanlines, mask, and vignette lower the rendered contrast, so test the rendered screen at the default shader settings and keep at least 4.5:1 for text. `crt off` restores the source contrast. The fallback page reuses the existing site styles and targets a Lighthouse accessibility score of 95 or higher.
- **Known limit.** Text on the CRT cannot be selected. Every post has a real page where selection works, and `open` goes there.

### Reading a post

`cat` fetches `post.url`, parses it with `DOMParser`, and reads the post body element from `_layouts/post.html`. `html-to-text.js` converts it:

- Headings print in upper case with an underline of `=` or `-`.
- Paragraphs wrap at the active column count (80 or 40).
- Code blocks print indented by two spaces, and lines longer than the column count minus 2 are cut with a `>` marker.
- Lists keep bullets or numbers.
- Links print as `text [n]`, with a numbered footnote list at the end.
- Images and embeds print as `[image: alt text]`.

If the body element is missing, the command prints an error and the real URL.

### Changes to the post layout

At M5, after the scene moves to `/`, `_layouts/post.html` gets one fixed link, "Back to the desk", pointing at `/#cat=<slug>`. The hash powers the machine on and runs `cat` for that post (see Timings). The link is hidden only when `document.referrer` is from a different origin. Direct visits, which have an empty referrer, and same-site visits see it.

| `posts.json`, gzipped | 10 KB or less |

| Time from page load to an interactive OFF scene | 2 s or less on a 4G connection and a 2021 mid-range phone |
| Render time per frame while READY | 16.6 ms or less on desktop, 22 ms or less on mobile |
| Frame rate while READY | 30 fps for 10 s after input, then only on canvas changes |
| Idle OFF scene | 0 frames rendered per second |

Measure bundle size in M0 with a bare scene (renderer, camera, one `RoundedBoxGeometry` mesh) before any app code exists. `WebGLRenderer` alone is large, so this number decides whether the budget holds. Measure frame time with a Chrome performance trace on a throttled 4x CPU profile, and with a real device before M5.

## Build and deploy

```
npm init -y
npm install --save-dev --save-exact esbuild vitest @playwright/test
npm install --save-exact three
```

Scripts:

| Command | Action |
| --- | --- |
| `npm run build` | `rm -rf assets/js/desk && esbuild desk-src/main.js --bundle --splitting --minify --format=esm --target=es2020 --legal-comments=eof --outdir=assets/js/desk`. Splitting makes the dynamic `import()` a separate chunk. The `rm` removes stale chunks. |
| `npm run dev` | Same without `--minify`, with `--watch` and a source map, next to `bundle exec jekyll serve`. The bundle is not committed, so run `npm run build` or `npm run dev` before the first `jekyll serve`, or `/desk/` cannot load `main.js` |
| `npm run size` | Prints the gzipped size of `main.js` and the scene chunk. Exits with code 1 if either exceeds its budget. |
| `npm test` | Vitest |
| `npm run e2e` | Playwright against `jekyll serve` |

The bundle is not committed. The workflow builds it on every push, so no commit can carry a stale bundle and the repository needs no pre-commit hook. A failing test or an over-budget chunk blocks the deploy instead of the commit.

Pin `esbuild` and `three` to exact versions in `package.json`, and commit `package-lock.json`. Then `npm ci` in the workflow installs the same versions as your machine, and the deployed bundle matches a local build. `--legal-comments=eof` keeps the three.js MIT notice in the bundle.

### Workflow

`.github/workflows/pages.yml` builds and deploys the site. It runs on every push to `master` and on manual dispatch (`workflow_dispatch`). It sets these permissions: `contents: read`, `pages: write`, and `id-token: write`. It uses the concurrency group `pages` with `cancel-in-progress: false`, so a deploy that has started finishes.

The `build` job runs on `ubuntu-latest` with these steps:

1. `actions/checkout`.
2. `actions/setup-node` with `node-version-file: .nvmrc` and `cache: npm`.
3. `ruby/setup-ruby` with `bundler-cache: true`. It reads `.ruby-version`, installs gems into `vendor/bundle`, and caches them.
4. `npm ci`.
5. `npm test`.
6. `npm run build`.
7. `npm run size`.
8. `npx playwright install --with-deps chromium`, then `npm run e2e`. The Playwright `webServer` setting starts `bundle exec jekyll serve`, so this step needs the bundle from step 6.
9. `actions/configure-pages`.
10. `bundle exec jekyll build` with `JEKYLL_ENV=production`.
11. `actions/upload-pages-artifact` with `path: _site`.

The `deploy` job needs `build`. It uses the `github-pages` environment and runs `actions/deploy-pages`.

Use the current major version of each action, and pin each one to a full commit SHA with the version in a comment.

### Switching the deploy

The switch happens once, in M0, in this order:

1. Build locally with `npm run build && bundle exec jekyll build`. Check that `_site` has every post at `/:title.html`, plus `/about/`, `/domains/`, `/category/tech.html`, `/category/misc.html`, `/category/ux.html`, `/feed.xml`, and `/assets/main.css`. The branch build also turns on plugins that the workflow does not load, such as `jekyll-optional-front-matter` and `jekyll-github-metadata`. No page in this repository depends on them. Every post and page has front matter, except `README.md`, which goes into `exclude`.
2. In the repository settings, go to **Pages** > **Build and deployment** > **Source**, and select **GitHub Actions**. The live site keeps serving the last branch build until the first workflow deploy.
3. Push the workflow and the `Gemfile`, `_config.yml`, and `.gitignore` changes to `master`.
4. Open the live site and check the same URLs as in step 1.

Step 2 is a setting, not a file, so the implementing agent cannot do it. The repository owner does it by hand.

Import only what the scene uses, such as `WebGLRenderer`, `Scene`, `PerspectiveCamera`, `Mesh`, and `RoundedBoxGeometry`, so esbuild can drop the rest.

## Testing

Unit tests with Vitest cover pure logic:

- Shell parser: quoting, pipes, empty input, unknown commands.
- Tab completion: command names, nested paths, ambiguous prefixes.
- Virtual file system: `cd` with `..`, absolute and relative paths, missing paths.
- `html-to-text.js`: headings, wrapping at 80 and at 40 columns, code blocks, link footnotes. Use three real posts from `_posts/` as fixtures.
- `power.js`: every legal transition, rejected illegal transitions, skip-boot behavior.
- Terminal buffer: scrollback limit, line wrap, cursor movement.

End-to-end tests with Playwright cover one path per environment:

1. Desktop Chromium. Open `/desk/`, press the hidden power button, wait for the prompt, type `ls posts/`, expect a known post name in the live region.
2. Desktop with WebGL disabled by an init script that makes `getContext("webgl2")` return null. Headless Chromium otherwise falls back to SwiftShader and keeps WebGL. Expect the plain list and working links.
3. iPhone 13 emulation. Tap the power button, expect the prompt in the 40-column layout, and expect no horizontal scroll.
4. `prefers-reduced-motion`. Press the power button and expect READY within 500 ms.
5. Keyboard only. Tab to the power button, press Enter, type a command, and press `Esc`. Expect focus on the mute button and the machine still READY.

The canvas check asserts that the WebGL canvas is not blank, with a pixel sample at the screen center. The sample calls `readPixels` in the same task as a render, or the test build sets `preserveDrawingBuffer: true`. Visual regression uses no pixel diffs.

Manual checks before each milestone ends: VoiceOver on Safari, keyboard-only pass, a real iPhone, and a real mid-range Android phone.

## Risks

| Risk | Likelihood | Effect | Mitigation |
| --- | --- | --- | --- |
| Scope grows in M1 (modeling by eye takes long) | High | Delay | Time-box M1 to 3 days. Ship plain boxes with good lighting. Detail comes later |
| Mobile keyboard hides the screen | Medium | Terminal unusable on phones | In focus mode on mobile, shift the camera up and use `visualViewport` to resize. Test on real devices in M2 |
| Terminal text is too small on phones | High | Unreadable screen | Pick the layout from the screen width in focus mode, and zoom in by itself in the narrow layout. Check legibility on a real phone in M2. Open question 6 covers the fallback to the plain list |
| Texture uploads exceed the mobile frame budget | Medium | Dropped frames while typing | Upload only dirty rows. Measure on a real phone in M2. If it is still too slow, use a 640 by 480 canvas in the narrow layout |
| Safari audio quirks | Medium | No sound on iOS | Resume the context inside a `click`, `pointerup`, or `keydown` handler, not `pointerdown`. Test early in M4 |
| Scene chunk exceeds its 200 KB budget | High | Slow load | M0 measured a bare scene at 131 KB gzipped, so the budget was raised from 145 KB. Import only needed three.js modules. `npm run size` fails the workflow before it deploys. If needed, replace `RoomEnvironment` and `PMREMGenerator` with a fixed environment color |
| Text on the CRT is hard to read | Medium | Poor usability | Keep distortion low. Offer `theme` and a `crt off` command that disables the shader's distortion and scanlines |
| Search engines index only the empty scene | Low | Traffic drop | Post pages are unchanged and linked from the in-DOM list. `sitemap` and feed stay as they are |
| The Jekyll 4 build differs from the current Pages build | Medium | Missing pages or feed after the switch | Compare the URL list before and after the switch (see Switching the deploy). Add `jekyll-feed` to the `Gemfile` |
| A broken workflow blocks posting | Low | New posts do not go live | The live site keeps serving the last deploy. Fix the workflow, or run it again with `workflow_dispatch` |

## Open questions

1. Start OFF or start READY? This draft starts OFF. If the prototype shows that visitors miss the button, switch to a one-time READY start with a prompted `shutdown` hint.
2. Should `/` serve the scene directly, or should `/` stay the post list with a prominent "Enter the desk" link? This draft promotes `/desk/` to `/` at M5. Revisit once traffic data from the prototype exists.
3. Which analytics, if any? The scene can count power-ons and `cat` commands with no cookies. Skip unless you want the data.
4. Is the graphical session (`startx` into an IceWM or fvwm95 desktop with a Windows 95 look) in scope for the first public release or a later one? This draft defers it to M6.
5. Which license and source for the final sound set, if you later replace synthesis with recordings? Synthesis avoids the question for now.
6. Should phones get the plain list by default, with the desk as an opt-in? This draft shows the desk in the 40-column layout. Decide after testing on a real phone in M2.

## Implementation notes

What differs from the plan above, and what is still open.

- **Scene chunk size.** The bare three.js scene was 131 KB gzipped, so the budget moved to 200 KB. The full scene, shell and audio are about 160 KB.
- **Font.** `vt323-subset.woff2` is the Latin subset of VT323 (17.9 KB). It has no box-drawing glyphs, so `tree` draws with `|--` and `` `-- ``.
- **Curvature.** The shader uses a radial barrel formula. The default is 0.05, because 0.08 bowed text rows too much to read.
- **Glow.** The screen glow is a transparent halo plane, brightest just outside the glass, as planned. It is not a light.
- **Power-on timing.** A press during POWERING, POST, or BOOTING never counts as skip input. Power-on happens on `click`, so no later `click` or `keyup` of the same gesture can skip. A held Enter on the hidden power button no longer repeats the click.
- **Idle spring-back.** The 6 s wait before the camera returns to center renders no frames. A timer wakes the loop when it ends.
- **Test hooks.** The root element carries `data-desk-state` and `data-desk-layout`. With `localStorage` key `desk.test` set to `1`, `window.__deskTest.point(name)` returns the client position of a part, for e2e clicks on props.
- **Wall.** M6 added a back wall behind the desk, for the clock.
- **Not done.**
  - Promotion is done at the owner's request, ahead of the M5 real-device checks. The scene is at `/`, `/desk/` redirects and keeps the hash, and posts have the "Back to the desk" link. Roll back by restoring `index.html` to `layout: home` if the checks fail.
  - Open question 6 (phones). The 40-column layout works in iPhone 13 emulation. A real phone decides it.
  - The `startx` desktop, which this doc defers to its own design note.
  - Frame cost on real devices. The loop measures CPU render time only, so a slow GPU does not trigger the pixel-ratio drop.
